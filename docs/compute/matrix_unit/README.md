# Matrix Unit diagrams

Figures for the [block specification](../bpu_matrix_unit_spec.md) and the
[I/O scheme](../matrix_unit_io_scheme.md): `bpu_matrix_unit` and everything under it, plus
the `sram_arbiter` Matrix channel. The SVGs in [svg/](svg) are generated by the unit owner's
scripts (the module cards are parsed from the RTL); [png/](png) holds 1:1 PNG copies for
chat and slides. Regenerate both whenever a port, parameter or block
changes.

| File | Shows |
| --- | --- |
| [matrix_unit_ports.svg](svg/matrix_unit_ports.svg) | The top-level ports of `bpu_matrix_unit`, what each connects to, and its default parameters. |
| [matrix_unit_structure.svg](svg/matrix_unit_structure.svg) | The blocks of `bpu_matrix_unit` and the wrapper, the data flow, and where each labelled assertion lives. |
| [matrix_unit_hierarchy.svg](svg/matrix_unit_hierarchy.svg) | The module hierarchy from `bpu_matrix_unit` down: every instance (name, module, count), the signals between them, and the logic written inline. |
| [matrix_unit_modules.svg](svg/matrix_unit_modules.svg) | One card per module (all nine) with its parameters and every port, parsed from the RTL headers. |
| [matrix_unit_timeline.svg](svg/matrix_unit_timeline.svg) | A schematic waveform of one block-scaled command, with the milestones, idle and the rules a checker can enforce. |
| [matrix_unit_8x8_array.svg](svg/matrix_unit_8x8_array.svg) | The 8 × 8 PE grid, its input delays, and the cycle the first k-step reaches each PE. |
| [matrix_unit_tile_walkthrough.svg](svg/matrix_unit_tile_walkthrough.svg) | One unscaled K = 64 tile through the array: filling, steady state, capture and drain. |

## Verification

Each requirement of the [block specification](../bpu_matrix_unit_spec.md) is mapped to its
tests in [bpu_matrix_unit_requirements.csv](../bpu_matrix_unit_requirements.csv). The
[test guide](../../../tb/compute/Matrix_Unit/README.md) describes every bench, the arbiter
models and the regression modes; `make test-matrix-unit` runs them all.

**Not covered yet:**
- coverage measurement for the current revision;
- formal proofs, for example of the credit and ordering rules, and of R02 and R17 (outputs
  that depend only on registers);
- the parameter-range checks (R33);
- the real `sram_arbiter` in the regression: rtl #35 is not merged, and a bench outside the
  regression runs it;
- integration with the controller and the Memory and Vector units, which have no RTL in the
  repository yet.
