## Results

Each PE configuration checks all 65,536 signed INT8 operand pairs on each of
two paths, once reading the shadow register and once reading the active
register. Across both accumulator widths, this gives **262,144 arithmetic
checks** and four reset-output checks. Incoming sums and carries are randomized;
the operand-pair enumeration does not exhaust all accumulator states.

Across the 15 array runs, the testbench checked **32,854 output columns**,
accepted **17,330 A rows**, observed **20,431 A-stall cycles**, and performed
**5,911 tile switches**. Of 32,953 input columns sent, 99 were cancelled by
reset. Every run satisfied `columns_checked = columns_sent - cancelled`.

Elapsed time is wall-clock runtime, including the CAE launcher and simulator
startup, excluding compilation. These measurements are not a hardware throughput
benchmark or a controlled simulator-speed comparison.

## Reproduce the VCS run

Use a licensed CAE Linux session with Git, Python 3, and the VCS module. Load
the module before enabling shell `nounset`; the site's module initialization
may read unset environment variables.

```bash
module load synopsys/vcs-mx/2026.03
git clone https://github.com/SiliconBadgers/rtl.git
cd rtl
git checkout 6d9b083fd7b6f1d2d0364e623fb6fcfde57d45d3
synopsys-run vcs -full64 -ID
```

Check that the compiler reports `Y-2026.03_Full64`. This source revision's
`run_tests.sh` supports Icarus and Verilator, not VCS. The following commands
reproduce the seven VCS builds and 17 simulations directly, keep per-case logs,
bound each process to 900 seconds, and fail on a nonzero exit or a missing PASS.
They do not enable coverage collection.

```bash
python3 - <<'PYTHON'
from pathlib import Path
import subprocess
import time

root = Path.cwd()
out = root / "build/matrix_unit/vcs-report"
out.mkdir(parents=True, exist_ok=True)
configs = [
    ("pe_acc32", "bpu_sa_pe_tb", {"AccW": 32}, [1]),
    ("pe_acc16", "bpu_sa_pe_tb", {"AccW": 16}, [1]),
    ("array_8x8_acc32", "bpu_sa_array_tb", {"Rows": 8, "Cols": 8, "AccW": 32}, [1, 2, 3]),
    ("array_3x5_acc32", "bpu_sa_array_tb", {"Rows": 3, "Cols": 5, "AccW": 32}, [1, 2, 3]),
    ("array_5x2_acc17", "bpu_sa_array_tb", {"Rows": 5, "Cols": 2, "AccW": 17}, [1, 2, 3]),
    ("array_1x1_acc16", "bpu_sa_array_tb", {"Rows": 1, "Cols": 1, "AccW": 16}, [1, 2, 3]),
    ("array_16x16_acc20", "bpu_sa_array_tb", {"Rows": 16, "Cols": 16, "AccW": 20}, [1, 2, 3]),
]


def run(command, log):
    start = time.monotonic()
    with log.open("w") as stream:
        subprocess.run(command, cwd=root, stdout=stream, stderr=subprocess.STDOUT,
                       timeout=900, check=True)
    print(f"{log.name}: {time.monotonic() - start:.3f} s")
    return log.read_text()


passed = 0
for name, top, params, seeds in configs:
    build = out / name
    build.mkdir(exist_ok=True)
    binary = build / "simv"
    run([
        "synopsys-run", "vcs", "-full64", "-sverilog", "-timescale=1ns/1ps",
        "-assert", "svaext", "-top", top,
        *[f"-pvalue+{top}.{key}={value}" for key, value in params.items()],
        "-f", "rtl/compute/Matrix_Unit/bpu_sa_array.f",
        f"tb/compute/Matrix_Unit/{top}.sv",
        f"-Mdir={build / 'csrc'}", "-o", str(binary),
    ], build / "compile.log")
    for seed in seeds:
        text = run(["synopsys-run", str(binary), "-exitstatus", f"+seed={seed}"],
                   build / f"seed{seed}.log")
        results = [line for line in text.splitlines() if line.startswith(f"RESULT {top} ")]
        if len(results) != 1 or "errors=0 status=PASS" not in results[0]:
            raise SystemExit(f"FAIL {name} seed {seed}: missing or failing result")
        print(results[0])
        passed += 1
if passed != 17:
    raise SystemExit(f"FAIL: expected 17 simulations, ran {passed}")
print("PASS: 17 planned, 17 run, 17 passed, 0 failed, 0 skipped")
PYTHON
```

Logs are written to `build/matrix_unit/vcs-report/<configuration>/`.
`compile.log` captures compilation, and `seed<seed>.log` captures each simulation.
The `-exitstatus` option is essential: in the initial VCS experiment, deliberately
failing simulations printed `$fatal` diagnostics but returned 0 without it.

The checks above establish correctness for the exercised input sequences. They
do not establish coverage closure or an untested-path percentage.

- The reset test on this revision does not explicitly fail if it never reaches
  active traffic. Passing these runs does not resolve that test-quality issue.

- These are block simulations, not an accelerator or full-SoC regression.
- Formal verification, synthesis, timing, gate-level simulation, CDC/reset
  analysis, and systematic X-propagation testing were not performed.
