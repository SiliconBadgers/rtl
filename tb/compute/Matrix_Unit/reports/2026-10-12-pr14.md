# Matrix-unit VCS verification, October 13, 2026

**17 planned, 17 run, 17 passed, 0 failed, 0 skipped** on Synopsys VCS
`Y-2026.03_Full64`. The regression checks 262,144 PE operand/path cases and
32,854 array output columns. Coverage was **not measured**.

[PR #14](https://github.com/SiliconBadgers/rtl/pull/14) partially implements
[matrix-unit issue #19](https://github.com/SiliconBadgers/rtl/issues/19).

## Environment and reproduction

Use licensed Linux, Bash 3.2+, Python 3.11+, Git and Make. On UW–Madison CAE:

```sh
module load synopsys/vcs-mx/2026.03
make doctor
make test-matrix-unit
python3 -m unittest discover -s scripts -p 'test_*.py'
make style
```

Run from the repository root at the tested commit listed in the PR's evidence
section. The source fingerprints below identify the files used for this run;
measurements were collected before committing, then checked against the saved
source contents.

The shared `scripts/vcs.py` verifies the exact compiler version, compiles with
`-full64 -sverilog -timescale=1ns/1ps -assert svaext`, runs `simv -exitstatus`,
and bounds compilation and simulation to 900 seconds. On CAE it invokes tools
through `synopsys-run`. Missing tools or another simulator choice fail early.

The default matrix run uses seed 1 for two PE configurations and seeds 1, 2, 3
for five array configurations. Rerun one case with:

```sh
make test-matrix-unit MATRIX_UNIT_ARGS="--only array_8x8_acc32 --seeds 2"
```

The generated `build/matrix_unit/vcs/summary.md` records results. Per-run logs
are in `build/matrix_unit/vcs/logs/`; compiler logs and elapsed times are in
`build/matrix_unit/vcs/build/<configuration>/`.

## Results

Every INT8 operand pair is checked through both PE register paths for each
accumulator width. Random incoming sums/carries do not exhaust all accumulator
states. Each array output column is checked for data, order and the specified
`Rows + Cols + 1` latency.

Across the array tests: 32,953 columns sent, 32,854 checked, 99 cancelled by
reset, 17,330 A rows accepted, 20,431 A-stall cycles, and 5,911 tile switches.
Every run enforces `checked = sent - cancelled`.

All 15 array runs observed reset during active work. All 12 multi-row runs also
observed reset during partial A-tile loading. The three 1x1 runs cannot partially
load a one-row tile. Missing reset prerequisites now fail the test explicitly.

Elapsed seconds include launcher and simulator startup, excluding compilation.
They are not accelerator performance measurements.

## Failure detection

Run these checks into separate directories; both commands must return 1:

```sh
bash tb/compute/Matrix_Unit/run_tests.sh --inject-failure --seeds 1 --out build/negative
bash tb/compute/Matrix_Unit/run_tests.sh --check-reset-guard --out build/reset_guard
```

| Check | Observed result |
| --- | --- |
| Corrupt one expected value in each of seven configurations | All seven detected the mismatch; simulator exit 3, runner exit 1 |
| Suppress traffic required for active reset | `active-reset precondition not reached`; simulator exit 3, runner exit 1 |
| Force the labeled stall assertion false in an isolated test copy | Assertion failure detected; simulator exit 3 |
| Tooling unit tests | 12 passed: timeout, exit propagation, missing executable, version/output rejection, simulator selection, and parameter/constant naming |
| `make style` | Passed Verible formatting/lint and Ruff checks |

The forced-assertion experiment used an isolated modified testbench and is not a
normal regression case. Failure diagnostics were checked as well as exit codes;
a build failure does not count as a successful negative test.

## Coverage and limits

| Measure | Result |
| --- | --- |
| Code coverage: line, branch, condition, toggle, FSM | Not measured; `-cm` was not enabled |
| Functional coverage | Not measured; no covergroup/bin report was collected |
| Assertion coverage | Not measured; enabled assertions do not imply a coverage report |
| Coverage database / URG report | None collected |

The regression establishes correctness for the exercised sequences. It does not
establish coverage closure. INT4 arithmetic is unimplemented; only its error
indication is checked. These are block tests, not full-SoC or inference results.
Formal verification, synthesis, timing, gate-level simulation, CDC/reset analysis
and systematic X-propagation testing were not performed.
